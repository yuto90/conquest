# Issue #116 移動速度の検証

## 対象と結論

- 比較元: `main@9bc3d55f873aa7d6bd0aa65385781123ea1cc370`
- 実行環境: FVM / Flutter 3.44.8 / Dart 3.12.2、Linux
- 固定viewportでは、元の距離比例計算と描画は既に等速だった。今回の固定盤面テストでは、リサイズを伴わない元の体感症状は再現していない。
- 再現した不具合は、飛行中の縦横比変更後も古い到着予定を保持し、画面上の移動距離だけが変わる経路。移動方向により表示速度が変わっていた。
- 修正は、不変の補間区間から同じゲーム内時刻の進捗を保持し、新しい実viewportの共通速度で残り時間を再計画する。通常の距離比例、10000msの対角基準、成長・到着順序は維持する。

## 独立した描画実測

`test/rendered_movement_test.dart` は実際の30dp配置枠のRenderBox中心を取得する。期待値は本番の座標・距離ヘルパーを使わず、文書の座標契約から計算する。出発・到着・リサイズをまたぐ差分は速度に含めない。

| 条件 | 比較元の速度範囲 (dp / ゲーム内秒) | 比較元の速度差 |
| --- | ---: | ---: |
| 390×844固定、短中長・水平垂直斜め逆方向 | 88.998764–89.014483 | 0.017662% |
| 400×400固定、同条件 | 52.323232–52.333805 | 0.020206% |
| 390×844 → 400×400、Controller経由の飛行中リサイズ | 40.459267–91.479650 | 126.103081% |

比較元の固定盤面行列は通常対戦／観戦、全難易度、両陣営、異なる兵力で成功。リサイズの同一fixtureは修正前に失敗し、修正後は **52.320243–52.327612 dp / ゲーム内秒、速度差0.014086%** で成功した。400×400盤面の理論速度は52.325902。

同一fixtureは4島を正規化座標 `(±0.65, ±0.4)` に置き、水平・垂直・斜め・逆方向へ出兵。200msでリサイズし、再レイアウト後50ms進めてから200ms区間の描画移動を測る。修正前の200ms移動量は8.091853–18.295930dp、修正後は10.464049–10.465522dp。

リサイズ後の既存部隊と新規部隊を混在させた追加行列も成功。速度差は0.110335%で、各移動計画のms丸め誤差境界内。判定は「1%以内」だけでなく、最大0.5msの丸めによる誤差境界も独立に確認する。
